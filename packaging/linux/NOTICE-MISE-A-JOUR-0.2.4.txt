========================================================================
NotesCam 0.2.4 — Notice pour l'administrateur du serveur de l'école
                 THE GENIUS
========================================================================

Cette version remplace la 0.2.3 (archive du 27/08/2026).

C'est une mise à jour COURTE : un seul ajout, à la caisse. Aucune
correction de données, aucune migration, aucune étape de durcissement
des rôles. Si vous avez déjà fait les étapes 2 et 3 de la notice 0.2.3,
il n'y a RIEN à refaire ici.


CE QU'APPORTE CETTE MISE À JOUR
-------------------------------
1. Imprimer les DEUX exemplaires d'un reçu sur une seule feuille A4.
   Jusqu'ici, pour donner son reçu au parent ET en garder un à la
   caisse, il fallait relancer l'impression une seconde fois : deux
   passages, donc deux occasions de se tromper de bouton ou d'oublier
   le talon de l'école.

   Deux nouveaux boutons apparaissent dans « Frais scolaires » :

     - « 2 reçus (A4) », juste après l'enregistrement d'un versement ;
     - « A4 x2 », dans l'historique, pour réimprimer.

   La feuille sort en A4 DEBOUT : l'exemplaire du parent en haut,
   l'exemplaire de l'école en bas, avec un trait de coupe au milieu.
   Chaque moitié est exactement le reçu A5 que vous connaissez.

   ⚠️ IMPORTANT — ce n'est PAS un second reçu. Les deux moitiés portent
     le MÊME numéro, le MÊME montant et le MÊME caissier : c'est une
     seule pièce comptable en deux exemplaires. Le talon du bas ne doit
     jamais être présenté comme la preuve d'un second versement.
     Une réimpression marque les DEUX moitiés « DUPLICATA ».

   Les deux boutons existants ne changent pas : « Imprimer le ticket »
   (rouleau 80 mm) et « Reçu A5 » (une seule moitié) restent là, au même
   endroit, avec le même comportement.


CE QUI N'EST PAS TOUCHÉ
-----------------------
  - Aucune donnée scolaire n'est modifiée : élèves, notes, bulletins,
    classes, frais, encaissements.
  - Aucun reçu déjà émis n'est modifié : les numéros restent les mêmes,
    un ancien reçu se réimprime à l'identique.
  - La base de données est CONSERVÉE (copie de sûreté automatique avant
    l'installation).
  - Le rattachement de l'école au Cloud est CONSERVÉ : aucun nouvel
    appairage, aucun code à saisir.
  - Les rôles et les secteurs ne bougent pas. Ne relancez PAS
    durcir-roles.sh : c'est déjà fait depuis la 0.2.3.
  - Aucun mot de passe n'est lu ni modifié.


CE QU'IL VOUS FAUT
------------------
  - Le fichier :
        notescam-linux-x64-0.2.4.tar.gz     (environ 50 Mo)
  - Le script deploy-correctif-credentials.sh, déjà reçu au 0.2.1.
  - Un accès au serveur Linux de l'école, avec les droits « sudo ».
  - Environ 5 minutes. Le service sera indisponible ~1 minute.

À faire de préférence en dehors des heures d'encaissement.


ÉTAPE 1 — INSTALLATION
----------------------
        cd ~
        ls -l notescam-linux-x64-0.2.4.tar.gz
        sudo ./deploy-correctif-credentials.sh notescam-linux-x64-0.2.4.tar.gz

   (Si NotesCam n'écoute pas sur le port 8080 — vérifiable avec
    « grep PORT /etc/notescam/notescam.env » — utilisez plutôt :
        sudo PORT=LE_PORT ./deploy-correctif-credentials.sh notescam-linux-x64-0.2.4.tar.gz )

Le script affiche un bloc « VERDICT » au bout de 2 minutes environ.

  ✅ « Toutes les vérifications locales sont PASS. »  -> étape 2.
  ❌ « N vérification(s) en échec »                   -> ne pas aller
     plus loin ; envoyer à l'éditeur le résultat de :
        sudo journalctl -u notescam --since '-10 min' --no-pager | tail -50


CONTRÔLE — la version est-elle bien en place ?
----------------------------------------------
        curl -s http://127.0.0.1:8080/api/version

  doit contenir : "version":"0.2.4"


ÉTAPE 2 — RECHARGER L'APPLICATION SUR LES POSTES
-------------------------------------------------
NotesCam garde une copie de l'application dans le navigateur, pour
fonctionner même quand le réseau tombe. Après l'installation, un poste
peut donc continuer d'afficher l'ANCIENNE version, sans les nouveaux
boutons — ce n'est pas une panne, c'est cette copie.

Sur le poste de la caisse (et sur tout poste qui imprime des reçus) :

        Ctrl + Maj + R          (rechargement forcé)

Si les boutons n'apparaissent toujours pas, fermez complètement le
navigateur et rouvrez-le.


VÉRIFICATION FINALE, À L'ÉCRAN
------------------------------
Avec le compte de la caisse :

  1. Frais scolaires -> ouvrir un élève -> enregistrer un versement.
     Le bandeau vert affiche maintenant TROIS boutons :
       « Imprimer le ticket »  ·  « 2 reçus (A4) »  ·  « Reçu A5 »
  2. Cliquer sur « 2 reçus (A4) » : l'aperçu d'impression montre UNE
     feuille A4 debout avec deux reçus, séparés par un trait de coupe.
     En bas de chaque moitié : « EXEMPLAIRE PARENT » et
     « EXEMPLAIRE ÉCOLE ».
  3. Vérifier que le numéro de reçu est le MÊME sur les deux moitiés.
  4. Dans l'historique des versements, le bouton « A4 x2 » ressort la
     même feuille, cette fois avec le bandeau « DUPLICATA » sur les
     deux moitiés.

⚠️ Dans la boîte d'impression du navigateur, laissez le format sur A4 et
  l'échelle sur « Taille réelle » / 100 %. Une échelle « Ajuster à la
  page » décale le trait de coupe.

Et en ligne de commande :

        systemctl is-active notescam                       -> active
        curl -s http://127.0.0.1:8080/api/version          -> 0.2.4
        curl -s http://127.0.0.1:8080/api/pair/status

  La dernière doit contenir
  "schoolId":"6b68407b-3d2e-426b-81ff-c4e68e66120a"
  (preuve que le rattachement au Cloud est intact).


EN CAS DE PROBLÈME
------------------
L'installation conserve tout. La copie de la base est déposée
automatiquement dans /var/lib/notescam/data/ :

        notescam.db.avant-correctif-<horodatage>

Ne la supprimez pas et ne la restaurez pas de vous-même : contactez
l'éditeur, qui vous guidera. L'archive de la version précédente
(notescam-linux-x64-0.2.3.tar.gz) permet un retour arrière complet.
