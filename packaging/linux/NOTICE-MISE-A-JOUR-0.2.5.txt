========================================================================
NotesCam 0.2.5 — Notice pour l'administrateur du serveur de l'école
                 THE GENIUS
========================================================================

Cette version remplace la 0.2.4.

Elle corrige le défaut que vous avez signalé : les informations des parents
qui ne s'affichaient pas sur la fiche des élèves, et qui disparaissaient
après l'enregistrement.

Aucune migration, aucune étape de durcissement des rôles, aucune donnée
scolaire modifiée.


1. CE QUI N'ALLAIT PAS, ET CE QUI EST CORRIGÉ
----------------------------------------------
Huit champs de la fiche élève — lieu de naissance, adresse, contact
d'urgence, nom et profession du père, nom et profession de la mère,
tuteur légal — n'étaient PAS enregistrés par le serveur de l'école.

Ce n'était pas un défaut d'affichage : c'était une perte à la saisie.
La secrétaire tapait le nom du père, enregistrait, l'écran affichait un
succès — et rien n'était écrit. L'information restait visible tant que la
page n'était pas rechargée, puis disparaissait. D'où l'impression que les
données « s'effacent toutes seules ».

Le téléphone du parent, lui, était bien enregistré : c'était le seul de
ces champs que le serveur savait stocker. C'est ce qui explique que vous
ayez des téléphones mais aucun nom de parent.

⚠️ CE QUI A ÉTÉ SAISI AVANT CETTE MISE À JOUR EST PERDU.
   Ces informations n'ont jamais été écrites, ni sur le serveur, ni dans
   le Cloud : il n'y a rien à récupérer. Après l'installation, il faudra
   les ressaisir.

   ➜ Si vous avez conservé le fichier CSV d'inscription qui contenait les
     parents, RÉIMPORTEZ-LE : les colonnes existent désormais et les
     valeurs seront reprises. C'est beaucoup plus rapide que la saisie.
     N'importez pas un fichier sans matricules : il créerait des doublons.

À partir de cette version, ces huit champs se saisissent, se conservent,
remontent au Cloud et reviennent sur les bulletins officiels et sur le
reçu (« responsable légal »), comme les autres.


2. NOUVEAU — LISTE DES ÉLÈVES INSCRITS À UN FRAIS
--------------------------------------------------
Dans « Frais scolaires » → onglet « Catalogue » :

  - une colonne « Inscrits » indique, pour chaque frais, combien d'élèves
    y ont souscrit ;
  - un bouton « Liste » imprime la liste de ces élèves.

Prévu pour le bus, la cantine, l'internat. La feuille porte l'en-tête
officiel, l'effectif en clair, un numéro d'ordre, les élèves groupés par
classe, puis le montant, le versé et le reste — par élève et en total.
Elle se remet telle quelle au chauffeur ou à la cantine.

À savoir : les classes y sont rangées par ordre alphabétique (« 2nde »
avant « 6e »). Les élèves d'une même classe sont bien ensemble ; c'est
seulement l'ordre des classes entre elles qui ne suit pas la progression
scolaire.

Un élève dont l'inscription a été retirée ne figure pas sur la liste.


3. NOUVEAU — NUMÉROTATION DE LA LISTE DES ÉLÈVES
-------------------------------------------------
La liste des élèves à l'écran porte maintenant un numéro d'ordre, comme
la liste imprimée l'avait déjà. La numérotation se poursuit d'une page à
l'autre : le dernier numéro de la dernière page est l'effectif filtré.


CE QUI N'EST PAS TOUCHÉ
-----------------------
  - Aucune donnée scolaire n'est modifiée : élèves, notes, bulletins,
    classes, frais, encaissements.
  - Aucun reçu déjà émis n'est modifié.
  - La base de données est CONSERVÉE (copie de sûreté automatique avant
    l'installation).
  - Le rattachement de l'école au Cloud est CONSERVÉ : aucun nouvel
    appairage, aucun code à saisir.
  - Les rôles et les secteurs ne bougent pas. Ne relancez PAS
    durcir-roles.sh : c'est fait depuis la 0.2.3.
  - Aucun mot de passe n'est lu ni modifié.


CE QU'IL VOUS FAUT
------------------
  - Le fichier :
        notescam-linux-x64-0.2.5.tar.gz     (environ 50 Mo)
  - Le script deploy-correctif-credentials.sh, déjà reçu au 0.2.1.
  - Un accès au serveur Linux de l'école, avec les droits « sudo ».
  - Environ 5 minutes. Le service sera indisponible ~1 minute.

À faire de préférence en dehors des heures de saisie.


ÉTAPE 1 — INSTALLATION
----------------------
        cd ~
        ls -l notescam-linux-x64-0.2.5.tar.gz
        sudo ./deploy-correctif-credentials.sh notescam-linux-x64-0.2.5.tar.gz

   (Si NotesCam n'écoute pas sur le port 8080 — vérifiable avec
    « grep PORT /etc/notescam/notescam.env » — utilisez plutôt :
        sudo PORT=LE_PORT ./deploy-correctif-credentials.sh notescam-linux-x64-0.2.5.tar.gz )

Le script affiche un bloc « VERDICT » au bout de 2 minutes environ.

  ✅ « Toutes les vérifications locales sont PASS. »  -> étape 2.
  ❌ « N vérification(s) en échec »                   -> ne pas aller
     plus loin ; envoyer à l'éditeur le résultat de :
        sudo journalctl -u notescam --since '-10 min' --no-pager | tail -50


CONTRÔLE — la version est-elle bien en place ?
----------------------------------------------
        curl -s http://127.0.0.1:8080/api/version

  doit contenir : "version":"0.2.5"

Au premier démarrage, le serveur journalise aussi :

        sudo journalctl -u notescam --since '-5 min' --no-pager | grep '\[db\]'

  Attendu : une ligne « colonne(s) ajoutée(s) sur table(s) synchronisée(s) »
  citant students.nom_pere, students.tuteur, etc., suivie de « curseur de
  pull remis à zéro ». C'est normal : le serveur relit le Cloud une fois
  pour remplir les colonnes neuves. La synchro qui suit est plus longue
  que d'habitude, une seule fois.


ÉTAPE 2 — RECHARGER L'APPLICATION SUR LES POSTES
-------------------------------------------------
NotesCam garde une copie de l'application dans le navigateur. Après
l'installation, un poste peut donc continuer d'afficher l'ANCIENNE
version — ce n'est pas une panne, c'est cette copie.

Sur chaque poste :

        Ctrl + Maj + R          (rechargement forcé)

Si l'écran n'a pas changé, fermez complètement le navigateur et rouvrez-le.


VÉRIFICATION FINALE, À L'ÉCRAN
------------------------------
  1. Élèves -> ouvrir une fiche -> Modifier : saisir un nom de père, un
     nom de mère et un tuteur, puis enregistrer.
  2. RECHARGER LA PAGE (F5). C'est l'étape qui compte : avant, c'est ici
     que les informations disparaissaient.
     Attendu : la section « Informations familiales » affiche toujours le
     père, la mère et le tuteur.
  3. Frais scolaires -> Catalogue : la colonne « Inscrits » affiche un
     effectif, et le bouton « Liste » sort la feuille des élèves inscrits.
  4. Élèves : la liste à l'écran est numérotée 1, 2, 3… et la numérotation
     continue en page 2.

Et en ligne de commande :

        systemctl is-active notescam                       -> active
        curl -s http://127.0.0.1:8080/api/version          -> 0.2.5
        curl -s http://127.0.0.1:8080/api/pair/status

  La dernière doit contenir
  "schoolId":"6b68407b-3d2e-426b-81ff-c4e68e66120a"
  (preuve que le rattachement au Cloud est intact).


EN CAS DE PROBLÈME
------------------
L'installation conserve tout. La copie de la base est déposée
automatiquement dans /var/lib/notescam/data/ :

        notescam.db.avant-correctif-<horodatage>

Ne la supprimez pas et ne la restaurez pas de vous-même : contactez
l'éditeur, qui vous guidera. L'archive de la version précédente
(notescam-linux-x64-0.2.4.tar.gz) permet un retour arrière complet.
